## Standards

- 恢复仅启动旧客户端就标记成功：已保存原组、provider 和完整规则基线，恢复后核对活动入口、结构及有效手选，再标记恢复完成。
- 拒绝覆盖后续修改前先暂停监测：改为先校验全部文件；回归用例确认拒绝时不会暂停原任务。
- 监测事务不在恢复顺序中：全部有持久记录的事务按先后恢复，监测恢复保留当前已应用方案；故障注入用例覆盖应用后监测及补偿失败、历史重试恢复。
- 重复设备锁与职责分散属于可维护性判断项：设备与旧工具互斥集中到 `device-lease.ts`；对话框和监测界面独立；自有源码采用统一格式。命令路由仍集中在应用入口，后续按业务规模演进。

收敛复查结果：3 项实质恢复问题均已修复，本次范围内无未解决严重问题；可维护性建议已落实主要重复逻辑抽取。

## Spec

- 已知远端主分支消失时当成空仓库：现在拒绝同步，并验证已知历史、发布请求和删除记录不被改写。
- 独立监测启动和停止没有持久事务：现在使用统一设备互斥与原状态记录；失败恢复原任务，新增替代任务被移除，已有任务按原 XML 恢复执行路径与参数。
- 迁移将宽泛 DIRECT 提到场景前：仅保留原先连续直连前缀为必要例外，其余迁移规则保留原顺序；首条路由回归覆盖专属 AI 规则先于宽泛直连。
- 恢复成功缺少原运行证据：同 Standards 的运行基线核验修复。
- 无效节点协议或端口覆盖有效快照：增加结构校验；已指定受支持内核时，在提交私有快照前做真实内核预检；失败保留最后有效快照并标陈旧。
- 复查补充：监测恢复排序、原任务归属，以及来源详情缺少停用与解绑入口，均已修复。来源目录与所有受影响方案的删除在同一 Git 提交中发布，残留远端引用会拒绝提交。

收敛复查结果：初查 5 项及复查 3 项均已处理；其中恢复运行证据、监测排序与 Standards 有交叉，不能简单相加为独立缺陷数。
