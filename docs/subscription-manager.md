# 独立订阅管理器使用说明

程序位于仓库根目录，便携 ZIP 的开发构建产物位于其 `release/`。解压后打开「Clash 订阅管理器.exe」，无需预装 Python、Node.js 或 Git。当前写入兼容基线为 Clash Verge Rev 2.5.8 与 Mihomo Meta v1.19.32 Windows amd64。配置数据保存在 Windows 用户应用数据目录，与程序目录分离；升级时退出管理器后解压新版，继续使用原数据。包内 `resources/manager-resources/bin/使用说明.md` 可离线查看。

## 首次接入

1. 在「连接与本机设置」点击自动发现。唯一候选会填入；多候选时手动选择客户端、内核和管理目录。
2. 点击「迁移现有聚合」，读取当前生成的组、规则及 provider，将现有候选固定下来。不执行第三方脚本。无法唯一识别或不支持的内容会阻止迁移，不会静默丢弃。
3. 审阅 default 草稿，可先复制另存方案。编辑、发布和应用互相独立。
4. 点击「预览并应用」，检查校验问题、文件变更和外部修改提示，再开始应用。需要退出时，从 Clash Verge 托盘正常退出，等待管理器预检、备份、启动及运行核验完成。

管理器保留旧聚合的本地入口 UID，使用新的专属 Merge/Script；旧扩展和记录保留。受支持的仓库同步入口会因绑定变化或无法识别新脚本而拒绝覆盖。不要再使用历史配置包整份导入来替换当前配置。需要交还旧工具时，从首次接管事务恢复，确认旧绑定恢复后再使用旧入口。

## 日常调整

- 左侧来源库支持登记、刷新、设置、绑定与全局删除。订阅地址只在本机私有目录保存，界面不会回显已有地址。
- 多选节点后拖入代理组，或点击「加入组」。筛选只影响当前选择，不保存自动加入条件；订阅新节点始终待选。节点消失或改名保留失效引用，应用前明确处理。
- 组可作为场景、策略或通用入口；支持手选、测速优选、顺序故障转移，拖动成员和组卡片排序。拖动「引用此组」可将组加入其他组。循环、空组和无效引用阻止应用。
- 删除组、成员或方案内来源时，先查看影响并选择替代出口，或明确移除相关引用。全局来源仍有方案引用时拒绝删除。
- 网站规则可以关联现有场景预设，先审阅增减再合入。自定义覆盖优先于预设；必要直连例外最优先。命中预览缺少 IP、进程或数据库上下文时会明确提示。
- 来源快照、原订阅卡片、运行 provider 分别记录。满足已应用方案与归属校验时，刷新固定节点的数据；失败保留快照和恢复记录。新增、删除来源及卡片结构修改需要正常退出后的应用事务。
- 流量、到期和刷新时点来自订阅元信息；缺失显示未知，获取失败保留旧快照并标注陈旧。运行加载、节点健康和网站实际可用是不同状态。

## 私有 Git 与多方案

使用专用的空私有仓库，或由本软件创建过的配置仓库。GitHub HTTPS 可在设置内点击登录，借助随包的凭据管理器打开系统浏览器完成认证；凭据由系统保管。其他服务器使用已有系统凭据或 SSH。地址不得包含令牌、用户名密码或查询参数。

- 「发布方案」分配该方案的新正式版本；「发布方案库与删除」原子提交所有本机方案、来源目录变化与删除记录。来源全局删除涉及远端其他方案时，先获取并修复全部引用。
- 版本格式为 `YYYY.MM.DD.序号`，同一方案采用更高版本整份覆盖，不自动合并两台电脑的内容。其他方案及历史版本保留。
- 获取覆盖本机编辑前保存恢复快照。新设备可先获取，再给共享来源绑定本机订阅；补齐节点前不允许应用。
- 远端可能已接收而本机未收到响应时，原请求持久保留。优先重试原发布；需要放弃待确认状态时，在同步设置中先核对远端结果，保留草稿，再决定获取或重新发布。
- 删除记录阻止旧草稿复活同一 ID。需要恢复已删除方案时，先恢复本机历史草稿，复制为新方案后发布。
- 发布与获取均不自动改变当前代理；订阅地址、节点凭据、控制器密钥、TUN、端口、当前选择和健康状态不上传。

## 恢复与后台运行

「历史与恢复」区分已发布历史、本机应用事务和草稿快照。恢复写入前校验备份摘要及当前文件，检测到后续修改会停止覆盖。崩溃留下的未完成事务阻止新写入；从恢复入口处理最近一次事务。客户端仍运行时，正常退出后再恢复完整配置。备份和新增文件留在 Clash Verge 本机管理目录，不上传 Git。

关闭窗口会进入托盘，管理器仍按来源周期刷新；显式退出管理器停止其刷新调度。已迁移并启用的专属线路稳定监测是独立计划任务，不随界面退出而停止；在「稳定池监测」中显式停止会清理动态优先值。软件只管理原有稳定池，未迁移的新设备不会自行启用。移动程序目录后，使用「启用／重新绑定程序」更新任务入口。

## 验收范围

自动验收覆盖脱敏目录中的故障恢复、固定成员、首条规则、旧同步器拒绝覆盖、临时 Git 远端与响应丢失重试，以及目标 Mihomo 隔离实例中的配置加载和 provider 热刷新。开发期离屏预览只使用演示数据。

真实首次接管、Clash Verge 托盘退出、Windows 登录任务执行、升级迁移及网站体验需要在实际设备上验收。程序已构建不等于活动配置已更新；配置已加载也不代表账号或全部网站可用。

开发、构建与测试命令见[应用 README](../README.md)。Mihomo 运行核验参照[官方 API](https://wiki.metacubex.one/api/)与[代理组配置](https://wiki.metacubex.one/config/proxy-groups/)，具体兼容结论以本机隔离用例为准。
